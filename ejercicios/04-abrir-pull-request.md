# Bloque 4 · Abre tu pull request (5:35–5:55 p. m.)

## Objetivo
Abrir un PR que explica tu cambio como decisión de diseño (resultado 3).

Un pull request (PR) es la propuesta de llevar los cambios de tu rama a `main`. Otra persona la revisa antes de integrarla.

## Pasos
1. Si cerraste la pantalla del bloque 3, entra a **Pull requests** > **New pull request**. Elige `main` como base y tu rama como compare.
2. Escribe un título que diga el cambio, por ejemplo "Título con el resultado del caso".
3. Completa la descripción que trae la plantilla: problema, qué cambiaste, por qué, antes y después, y qué revisar.
4. Para el antes y después, toma una captura de tu URL actual (antes) y una de la vista previa del editor (después). Arrástralas o pégalas en la tabla.
5. Selecciona **Create pull request**.
6. Copia el enlace del PR y pégalo en el formulario. Luego agrégalo al tablero de propuestas.

Los últimos minutos del bloque sirven para ponerte al día si vas atrasado.

## Resultado esperado
Tu PR está abierto, con la descripción completa y las dos capturas.

## Enlace de evidencia
`github.com/tu-usuario/ficha-de-caso/pull/1` en el formulario.

## Variante asíncrona (grabación)
Mira el capítulo 4. Si no tienes capturas, describe el antes y el después en una frase cada uno. Agrega tu PR al tablero: así otras personas que ven la grabación pueden revisarlo.
